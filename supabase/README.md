# Сервер профилей

Приложение обслуживает GitHub Pages. Supabase Auth принимает почту и пароль, отправляет коды и управляет сессиями. PostgreSQL хранит имя, ник и уменьшенную фотографию. Политики доступа разрешают пользователю читать и редактировать только свою запись. Профиль создаётся вместе с учётной записью. При удалении учётной записи в Supabase её профиль удаляется автоматически.

Учебный прогресс, избранное и личные рецепты привязаны к браузеру. Гостевой доступ работает офлайн. Пустые значения в `profile-config.js` включают существующий деморежим. После переключения на сервер пользователи локальных профилей регистрируются заново. Их локальные данные и пробные пароли на сервер не передаются.

## Локальный запуск

1. Установите Docker и Supabase CLI. Из корня репозитория выполните `supabase start`. CLI применит миграции из `supabase/migrations` и запустит локальную почту Mailpit.
2. В `profile-config.js` укажите локальный API URL и **публичный** ключ из `supabase status`. Подходят publishable key или прежний ключ с ролью anon.
3. Запустите `python3 -m http.server 3000 --bind 127.0.0.1` и откройте http://127.0.0.1:3000 в новом профиле браузера. Зарегистрируйтесь через вкладку «Профиль». Код появится в Mailpit по адресу http://127.0.0.1:54324.
4. При необходимости запустите браузерную проверку из корня репозитория. Она создаёт два тестовых аккаунта в локальной базе, читает коды из Mailpit и проверяет регистрацию, вход с другого устройства, редактирование, восстановление пароля и ограничения доступа.

```sh
python3 -m venv /tmp/pharma-profile-test
/tmp/pharma-profile-test/bin/pip install playwright
/tmp/pharma-profile-test/bin/playwright install chromium
/tmp/pharma-profile-test/bin/python supabase/tests/profile_smoke.py
```

Для установленных отдельно Chromium, приложения или Mailpit задайте соответственно `CHROMIUM_PATH`, `PROFILE_TEST_APP` или `PROFILE_TEST_MAIL`. Используйте локальные адреса. После работы остановите сервисы командой `supabase stop` и верните настройки приложения из локального режима к нужным для публикации.

## Подключение рабочего проекта

1. Создайте проект на бесплатном тарифе Supabase. Сохраните пароль базы в менеджере паролей. В разделе Data API включите API и убедитесь, что схема `public` доступна. Миграция сама выдаёт необходимые права на таблицу.
2. В корне репозитория выполните следующие команды. Для `--project-ref` используйте идентификатор именно того проекта, в котором должны храниться профили.

   ```sh
   supabase login
   supabase link --project-ref YOUR_PROJECT_REF
   supabase db push --dry-run
   supabase db push
   ```

3. В Authentication укажите Site URL приложения `https://mi-plus-dev.github.io/pharma_tests/`. Разрешите регистрацию по Email, включите обязательное подтверждение адреса и задайте минимальную длину пароля 8 символов. Для кодов задайте длину 6 цифр, срок действия 600 секунд и интервал между письмами 60 секунд. Настройки `config.toml` предназначены для локального стенда. Команда `db push` переносит только миграции.
4. В Email Templates вставьте содержимое [confirmation.html](templates/confirmation.html) в шаблон **Confirm signup**, а [recovery.html](templates/recovery.html) в **Reset password**. Русские темы писем указаны в [config.toml](config.toml). Код подставляет Supabase через `{{ .Token }}`.
5. Включите собственный SMTP в настройках Auth. Подойдёт, например, Resend. Подтвердите домен отправителя через DNS и перенесите в Supabase адрес отправителя и SMTP-реквизиты из панели почтового сервиса. Настройте лимит отправки в Supabase с учётом квоты провайдера. Встроенная почта Supabase рассчитана на адреса команды проекта. [Документация SMTP](https://supabase.com/docs/guides/auth/auth-smtp)
6. Впишите в `profile-config.js` URL проекта и его публичный ключ из раздела Connect или API Keys. Серверные ключи, пароль базы и пароль SMTP должны храниться только у администратора и в настройках сервиса.

   ```js
   const profileServer = Object.freeze({
     url: 'https://YOUR_PROJECT_REF.supabase.co',
     publishableKey: 'YOUR_PUBLISHABLE_KEY'
   });
   ```

7. Увеличьте версию кэша в `sw.js` и опубликуйте обновлённый сайт обычным способом. Проверьте на подконтрольном внешнем ящике получение обоих писем, вход после подтверждения и открытие профиля во втором браузере. Для возврата к деморежиму очистите оба значения конфигурации и выпустите новую версию кэша.

## Обновление клиента Auth

В приложение включена локальная сборка официального пакета `@supabase/auth-js`. Для пересборки выполните `npm ci`, затем `npm run build` из `tools/auth-sdk`. Готовый модуль и лицензии лежат в `vendor/`.
